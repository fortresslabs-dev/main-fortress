## Working notes

- **Order is load-bearing.** Phase-0 meta first so subsequent items have a place to land evidence. Phase-1 docs add nothing to AWS-account state. Phase-2 only adds new resources (Flow Logs, access logs, Access Analyzer) — none change existing routes/policies. Phase-3 flips that *will* surface findings (Inspector backlog, log-retention cost). Phase-4 last because it changes a prod default and needs a CI gate built alongside.
- **What this tracker does NOT cover (intentional):** Phase-1 closes 2 of 10 §13.1 hard blockers in full (B1, B3) and partials of 2 more (B7, B9) plus compensating control for B4. The other six (B2 MFA, B5 Marketplace APIs, B6 Portal, B7 *full*, B8 Policies, B10 Pen test) need owner assignment before adding here.
- **Evidence directory layout (item A4):**
  ```
  docs/ftr_evidence/
    01_wafr/              # WAFR self-assessment + partner-led review report (TBD)
    02_arch_diagram/      # PNG/PDF lifted from WAFR §2.1/§2.2
    03_security_tools/    # GuardDuty, Security Hub, Inspector, Access Analyzer screenshots / exports
    04_self_assessment/   # AWS Partner Central FTR checklist export
    README.md             # what lives where + how to refresh
  ```
- **Submission format reminder.** This tracker and the FTR doc are *internal* artifacts. The AWS-format submission is the AWS Partner Central FTR self-assessment form + uploaded evidence artifacts from `docs/ftr_evidence/`. We do not submit these markdown files to AWS; they are the pre-flight workpapers.
